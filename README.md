# Hosts Manager GUI

[English](README.en.md) | Русский

> [!WARNING]
> Проект, включая исходный код и документацию, полностью написан с использованием
> ИИ и не проходил независимый аудит безопасности. Перед использованием внимательно
> проверьте код, настройки путей и резервное копирование. Приложение изменяет системный
> файл `hosts` с правами администратора — используйте его на свой риск.

Desktop-приложение для управления отдельным HMG-блоком в системном файле `hosts`.
Интерфейс построен на PySide6/Qt и использует тёмную QSS-тему.

## Запуск

Требуется Python 3.11+ и [uv](https://docs.astral.sh/uv/).

```bash
make setup
make run
```

Приложение хранит расширенное состояние доменов отдельно и автоматически
сохраняет изменения записей, групп и источников в local state. Системный `hosts`
изменяется только вручную после просмотра diff; при необходимости приложение
запрашивает права администратора.

## Настройки и каталоги

Основной `settings.json` всегда хранится в стандартном пользовательском config-каталоге
текущей платформы. В разделе «Настройки» можно выбрать:

- каталог данных (`state.json` и `sources.json`);
- каталог логов;
- уровень логирования;
- максимальный размер одного файла (`KB`, `MB`, `GB`);
- количество rotated-файлов;
- срок хранения логов (`min`, `h`, `d`);
- необходимость файлового лога в development-режиме.

При смене каталога приложение предлагает скопировать существующие данные. Точные
системные пути отображаются в окне настроек и определяются через `platformdirs`.
Для portable/автоматизированного запуска начальные каталоги можно переопределить
переменными `HMG_CONFIG_DIR`, `HMG_DATA_DIR` и `HMG_LOG_DIR`.

В development-режиме логи по умолчанию выводятся только в stdout. В собранном
приложении консоль отключена, а JSON-логи пишутся в rotating-файл `hmg.log`.

## Импорт

Окно импорта принимает TXT с парами `domain IP`, CSV/TSV со столбцами
`domain` и `ip`/`ips`, а также JSON-массив объектов. Данные можно вставить
вручную, выбрать через диалог файла или перетащить файл в поле. До применения
отображается число распознанных доменов и связей домен/IP; ошибки TXT/CSV/TSV
привязаны к номеру строки, а ошибки синтаксиса JSON — к строке и колонке.

## URL-источники

В окне «Источники» можно сохранить несколько HTTP/HTTPS-адресов, включать их
и задавать порядок применения. Управление списком отделено от загрузки данных:
операция запускается кнопкой «Загрузка из URL» в главном окне. Поддерживаются
обычный hosts-формат (`IP domain`), CSV/TSV, JSON и формат `domain IP`.

- «Загрузить новые» только добавляет данные источников.
- «Синхронизировать» также удаляет исчезнувшие из источника связи.
- «Заменить целиком» создаёт список только из активных источников.

Источники загружаются последовательно, процесс можно отменить между источниками.
После загрузки приложение показывает отдельный результат или ошибку для каждого
URL и общий preview изменений. Local state изменяется только после явного
подтверждения. Источник с ошибкой пропускается без удаления его прежних связей;
полная замена при любой ошибке блокируется.

Изменения списка URL-источников применяются кнопкой «Сохранить». Кнопка «Отмена»
закрывает окно без изменения источников.
Происхождение отслеживается отдельно для каждой пары домен/IP в `sources.json`.
Ручные записи и состояние «Включено» при синхронизации сохраняются.
Любое действие с URL-источниками обновляет только внутреннее состояние приложения.
Системный файл `hosts` не изменяется автоматически: diff просматривается через
«Предпросмотр», а запись выполняется отдельно кнопкой «Сохранить в hosts».
Автоматическая синхронизация URL-источников при запуске не выполняется.

## Группы

Домены можно визуально разделять на группы и переносить между ними по одному
или сразу несколько. `Default` всегда находится первой: её нельзя удалить,
переименовать или переместить, а новые домены из импорта и URL-источников
попадают именно туда.

Переключатель группы временно исключает все её домены из итогового `hosts`,
не изменяя индивидуальные переключатели записей. Группы и отключённые записи
не создают в `hosts` комментариев: в управляемом блоке находятся только
активные домены из активных групп.

Главный список поддерживает поиск по домену и IP, фильтры по состоянию, группе
и источнику, а также сворачивание групп. После выбора одной или нескольких строк
становятся доступны контекстные действия: редактирование, перенос, массовое
включение/отключение и удаление. Статус внизу показывает число доменов, которые
сохранены в local state, но ещё не применены в системный `hosts`. Полные значения
домена и происхождения доступны через tooltip и контекстное копирование.

Предпросмотр `hosts` отдельно обозначает добавленные, удалённые, изменённые и
служебные строки. Изменение `Generated at` не входит в пользовательскую
статистику. Длинные неизменённые участки сворачиваются, а кнопки
«Предыдущее»/«Следующее» позволяют переходить между изменениями.

Успешные некритичные операции отображаются в статусном сообщении главного окна
и не требуют закрывать модальный диалог. В подтверждениях опасных действий
используются конкретные кнопки вроде «Удалить записи» или
«Закрыть без применения» вместо неоднозначных «Да»/«Нет».

## Проверки

```bash
make check
```

Команда запускает Ruff, mypy, аудит известных уязвимостей через `uv audit`
и тесты. Все эти проверки также выполняются pre-commit-хуками:

```bash
make install-hooks
make pre-commit
```

## Сборка приложения

PyInstaller создаёт один исполняемый файл для текущей операционной системы:

```bash
make build-app
```

Результат находится в `dist/hosts-manager-gui` (`.exe` на Windows). PyInstaller
не поддерживает cross-compilation, поэтому workflow `.github/workflows/build-app.yml`
собирает Linux, Windows и macOS параллельно на нативных GitHub runner'ах. Workflow
запускается вручную или при публикации тега `v*`.

Сборки пока не подписываются сертификатами разработчика, поэтому macOS Gatekeeper
и Windows SmartScreen могут показывать предупреждение до настройки code signing.

### Локальная сборка через Docker

Docker Buildx позволяет локально собрать Linux one-file binary независимо от
операционной системы хоста:

```bash
# Linux amd64
make build-linux-docker

# Linux arm64
make build-linux-arm64-docker

# Обе архитектуры
make build-linux-docker-all
```

Артефакты появляются в `dist/docker/linux-amd64` и
`dist/docker/linux-arm64`.

amd64-артефакт рассчитан на Debian 12 / glibc 2.36 или новее. ARM64 собирается
на Debian 13 и рассчитан на glibc 2.41 или новее: актуальные ARM64-колёса
PySide6 уже требуют как минимум glibc 2.39.

Docker использует Linux-ядро и не может создать нативные macOS/Windows-приложения.
Для них используется `make build-app` на соответствующей ОС. Wine-сборка Windows
намеренно не используется, поскольку PyInstaller официально не поддерживает такой
cross-compilation и результат нельзя считать воспроизводимым.
